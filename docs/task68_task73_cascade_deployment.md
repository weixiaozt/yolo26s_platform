# 项目38：任务68 + 任务73 两级级联部署说明

更新：2026-07-29

## 目的

一级实例分割模型保持极低阈值，以优先保证缺陷召回；二级分类模型只在高把握为 OK 时删除一级候选，用于降低倒角等假阳性。

## 模型与类别

| 阶段 | 训练任务 | OpenVINO 模型 | 类别 |
| --- | ---: | --- | --- |
| 一级 | 68 | `yolo11n-seg` | `隐裂 / 崩边 / 缺口` |
| 二级 | 73 | `yolo11n-cls` | `0=隐裂, 1=崩边, 2=缺口, 3=OK` |

二级模型原训练目录使用英文名 `Crack / EdgeChip / Notch / OK`。生产端需要使用中文元数据版本时，只能修改 OpenVINO 模型目录中的 `metadata.yaml`，不修改 `best.xml` 或 `best.bin`：

```yaml
names:
  0: 隐裂
  1: 崩边
  2: 缺口
  3: OK
```

生产端存在按文本读取 YAML 的实现时，上述值必须是裸 UTF-8 中文，不可写成 `\uXXXX`，也不可添加引号。

## 已验证参数

```text
一级：resize=2048, tile=640, overlap=0.2, padding=32
一级：conf=0.01, NMS IoU=0.5, 形态学三通道=启用, 膨胀核=3, 腐蚀核=3
二级：P(OK) >= 0.70 才否决一级候选
```

二级决策：

```text
二级预测 OK 且 P(OK) >= 0.70  -> 删除该一级候选
二级预测非 OK                  -> 保留，采用二级类别
二级预测 OK 但 P(OK) < 0.70   -> 保留，沿用一级类别
```

建议单图候选上限至少设为 50。验证集中出现过 25 和 27 个一级候选；上限为 20 会截断候选并可能引入实例漏检。碎片合并、亮度跳过、尺寸过滤均未纳入本次基准验证，首次生产复测应关闭或保持等效无过滤。

## 55 张人工复核生产图结果

测试集包含 34 张 OK、7 张崩边、6 张缺口、8 张隐裂。使用 OpenVINO FP16，一级运行在 Intel GPU.0、二级运行在 CPU：

| 指标（OK 阈值 0.70） | 结果 |
| --- | ---: |
| OK 图误报 | 0 / 34 |
| NG 图检出 | 21 / 21 |
| 一级候选 | 381 |
| 二级后保留 NG 候选 | 204 |
| 稳态总耗时 | 0.788 秒 / 图 |
| P95 总耗时 | 1.302 秒 / 图 |

这是一份图级结论：每张 NG 图至少存在一个保留的正确类别，不代表逐实例数量已经完成验收。

同一批图上，FP16 与 FP32 的一级候选框、类别、置信度和二级 Top-1 均一致；FP32 稳态平均为 0.895 秒 / 图，FP16 快约 11.9%。开发机为 i5-12450H；部署到 i7-12700 后仍需复测 CT 与逐图结果。

## 可复现工具

- `tools/eval_cascade_openvino.py`：完整 55 图级联验证，输出逐图、逐候选 CSV 与叠加图。
- `tools/export_cascade_review_crops.py`：导出二级实际接收的小图，按最终结果分组以便人工复核。
- `tools/run_single_cascade.py`：按相同参数测试单张生产图。
- `tools/export_fp32_comparison.py`：导出隔离 FP32 OpenVINO 副本，用于与 FP16 对比。

模型、OpenVINO 导出目录、复核小图和部署 zip 均属于 `storage/` 运行产物，不提交 Git。
