# 离线锁死部署手册（1050ti 机器）

面向场景：把平台部署到一台 **完全离线**、装了 **GTX 1050ti** 的机器；日常使用者只有 **普通 Windows 账号**，**不能看到源码**。

**核心思路**：你（管理员）一次性装好 → 全部做成 **Windows 服务**（开机自启、后台跑）→ 用 **NTFS 权限锁死代码目录**。之后使用者开机只需打开浏览器 `http://localhost:8000`，全程不碰文件、不碰命令行；他没有管理员权，`.py` 源码根本打不开。

> 只做「OS 文件权限锁死」这一层。没有混淆/编译/加密——因为使用者是普通账号，OS 权限就是最硬的墙。

> **目标机文件夹叫什么都行**（本手册用 `D:\VPvision_AI` 举例）：app 全用相对项目根的路径、部署脚本自动识别自己所在目录，都不依赖具体名字。下面「构建机」指你自己的开发机（还是 `D:\yolo26s_platform`），「目标机」指要部署的 1050ti 机（`D:\VPvision_AI`）。

---

## 0. 防护效果一览

| 资产 | 怎么防 |
|---|---|
| 后端 Python 源码、venv | NTFS ACL 拒绝普通账号读取；服务以 SYSTEM 身份跑 |
| 前端 | `npm run build` 出 `web/dist`，由后端托管，**目标机不装 node**，无 `.vue` 源码 |
| app 内权限 | 给他 `role='user'` 账号：删项目/改类别/导出模型/合并导入 等一律后端 403 |
| 模型 `.pt` / 数据 | 按你的要求**不额外加密**（ACL 已让他碰不到文件） |

## 1. 在「构建机」上准备离线包（有网的机器，Win x64 + Python 3.11）

目标机离线，所有东西要先在一台有网、**同架构**的机器上备好，再拷过去。

### 1.1 依赖 wheel 缓存（关键）
```powershell
cd D:\yolo26s_platform
python -m venv venv & venv\Scripts\activate
mkdir wheelhouse
pip download -r server\requirements.txt -d wheelhouse -i https://pypi.tuna.tsinghua.edu.cn/simple
REM 1050ti 用 CUDA 版 torch（Pascal 架构，cu124 支持）
pip download torch torchvision --index-url https://download.pytorch.org/whl/cu124 -d wheelhouse
pip download openvino onnx onnxslim onnxruntime -d wheelhouse -i https://pypi.tuna.tsinghua.edu.cn/simple
```
> `wheelhouse\` 会有几 GB（torch cu124 wheel 大）。这是目标机离线装依赖的来源。

### 1.2 前端构建产物
```powershell
cd D:\yolo26s_platform\web
npm run build      REM 若严格类型检查报历史错，用：  npx vite build
```
产出 `web\dist\`（后端会托管它，目标机无需 node）。

### 1.3 打一个拷贝包
把这些拷到 U 盘/移动硬盘（**不含 venv**，venv 到目标机重建，避免解释器路径坑）：
```
server\  core\  web\dist\  deploy\  docs\  tools\  requirements(server\requirements.txt)
wheelhouse\   .env.example   *.pt(预训练/已训练权重)   storage\ 的空骨架
Python 3.11 离线安装包 / MySQL 离线包 / Redis 离线包 / NVIDIA 驱动 / nssm.exe
```

## 2. 目标机一次性安装（用管理员账号操作）

1. **NVIDIA 驱动**：装 1050ti 驱动即可。torch 的 cu124 wheel 自带 CUDA runtime，**不用单独装 CUDA Toolkit**。
2. **Python 3.11**（python.org 离线包），勾选 Add to PATH。
3. **MySQL 8**（离线包），装成 Windows 服务，root 密码按 `.env` 设；建库：
   ```powershell
   mysql -u root -p123456 -e "CREATE DATABASE IF NOT EXISTS yolo_seg CHARACTER SET utf8mb4;"
   ```
4. **Redis**（离线包），装成 Windows 服务，端口 6379。
5. 把拷贝包解压到 **`D:\VPvision_AI`**（路径别带中文/空格；名字随意，脚本自动识别）。
6. **重建 venv + 离线装依赖**：
   ```powershell
   cd D:\VPvision_AI
   python -m venv venv & venv\Scripts\activate
   pip install --no-index --find-links=wheelhouse -r server\requirements.txt
   pip install --no-index --find-links=wheelhouse torch torchvision openvino onnx onnxslim onnxruntime
   ```
   > 用 `--no-index --find-links=wheelhouse` 纯离线装，不联网。
   > ⚠️ 别直接拷别的机器的 venv：`pyvenv.cfg` 里的解释器路径在这台机器不存在会报 "Unable to create process"。
7. **配置 `.env`**：`copy .env.example .env`，改 `DATABASE_URL` 密码、`JWT_SECRET=<随机长串>`。
8. **验证能手动跑一次**（确认再做成服务）：
   ```powershell
   $env:YOLO_AUTOINSTALL="False"; uvicorn server.main:app --host 0.0.0.0 --port 8000
   ```
   浏览器开 `http://localhost:8000` → 见到登录页即成功（后端已托管前端）。Ctrl+C 停。

> **1050ti 只有 4GB 显存**：训练只能小模型 `yolo11n` + batch 2~4 + imgsz 640；选 s/m/l 会 OOM。推理没问题。

## 3. 做成 Windows 服务（`deploy\install_services.bat`）

把 `nssm.exe` 放到 `deploy\` 目录，**以管理员身份**运行：
```
deploy\install_services.bat
```
它会注册两个服务并设为开机自启：
- **VP_backend** — uvicorn，同时提供 API + 前端界面（端口 8000）
- **VP_celery** — 训练队列 worker（pool=solo）

> 运行前按需改脚本顶部的 `MYSQL_SVC` / `REDIS_SVC` 为你实际的服务名（`sc query state= all | findstr /i "mysql redis"` 查）。
> MySQL/Redis 本就是服务，脚本用 `DependOnService` 保证它们先起。

管理：`services.msc`，或 `nssm edit VP_backend`。日志在 `logs\`。

---

## 4. OS 锁死（`deploy\lockdown_acl.bat`）

编辑脚本顶部 `WORKER_USER=` 为使用者的 Windows 账号名，**以管理员身份**运行：
```
deploy\lockdown_acl.bat
```
它用 `icacls` 把 `D:\VPvision_AI` 设为：**只有 SYSTEM（跑服务的身份）和 Administrators 能访问，那个普通账号全拒**。服务照常跑，他只能通过浏览器用，进不了目录、打不开 `.py`。

解锁（以后你要维护时，管理员执行）：
```
icacls "D:\VPvision_AI" /remove:d "账号名"
icacls "D:\VPvision_AI" /inheritance:e
```

## 5. 账号

- **Windows 账号**：给使用者建一个**普通用户**（非管理员）日常登录。
- **app 账号**：用 admin 登录 → 用户管理 → 新建一个 **role=普通用户** 账号给他。
  - 他能：上传/标注/训练/推理/看数据/存训练参数/导出项目数据包/取消训练。
  - 他不能（后端 403）：新建/改/删项目、改缺陷类别、删图、删训练任务、**导出/下载模型**、合并/导入项目、批量导入标注。
  - （按钮仍显示，点了会提示"该操作需要管理员权限"，数据不受影响，不会掉线。）
- 可选：他账号开机自动打开浏览器到 `http://localhost:8000`（放个快捷方式到 `shell:startup`）。
- **改默认密码**：登录后侧边栏底部「修改密码」，把 admin/admin123 改掉。

## 6. 验收清单

| 项 | 期望 |
|---|---|
| 用使用者的普通账号登录 Windows，开浏览器 `http://localhost:8000` | 能用 |
| 使用者试图打开 `D:\VPvision_AI` | 拒绝访问 |
| 重启机器 | 服务自启，浏览器直接能用 |
| 用 role=user 登录 app，点"删除项目" | 提示"需要管理员权限"，项目还在 |
| 训练一个 yolo11n 小任务 | 能跑（4GB 显存够） |

---

## 7. 日常维护（你，管理员）

1. 用**你的管理员账号**登录 Windows（有权访问目录）。
2. 停服务：`net stop VP_backend & net stop VP_celery`。
3. 更新代码（保留 `.env` 和 `storage\`），前端重新 `npx vite build`。
4. 起服务：`net start VP_backend & net start VP_celery`。
5. 改了库结构会在后端启动时自动迁移（`server\database.py` 的 ALTER 列表）。

## 8. 常见问题

| 问题 | 处理 |
|---|---|
| 服务起不来 | 看 `logs\backend.err.log` / `logs\celery.err.log` |
| 页面能开但接口 401/报错 | MySQL/Redis 服务没起，或 `.env` 数据库密码不对 |
| 训练一直"排队中" | VP_celery 服务没跑 |
| 训练 OOM | 换 yolo11n + 调小 batch/imgsz（1050ti 只有 4GB） |
| 使用者能进目录 | 他是不是本机管理员？锁死只在他是普通账号时成立 |
| 换机器换硬盘怕被拷走 | 本方案不防整机搬走；需要的话另加 BitLocker 全盘加密 |
